# Semantic Word Bench

Воспроизводимая игра для проверки семантического поиска языковых моделей. В версии v1 есть 10 русских и 10 английских скрытых слов. Для каждого языка зафиксирован словарь из 50 000 слов. Игрок видит ранг своей попытки относительно ответа. Ранг 1 означает победу.

Это пилотный бенчмарк поиска с обратной связью. Он не измеряет общий интеллект и не заменяет проверку модели на рабочих задачах. Сравнивается модель вместе с её агентом и инструментами.

## Запуск

Нужен Python 3.11 или новее. Для игры внешние пакеты, GPU и ключи API не нужны. Таблицы оценок уже включены в репозиторий.

```sh
python -m wordbench check-data
python -m wordbench serve
```

Открой http://127.0.0.1:8765. Создай запуск, укажи точное название модели, провайдера, режим рассуждения и интерфейс. Для каждого раунда скопируй его промпт в новый чат модели. После завершения 20 раундов скачай JSON во вкладке результатов.

Ссылки содержат идентификатор запуска и раунда. Их можно сохранить и открыть после перезапуска сервера. Попытки хранятся в `runs/benchmark.sqlite3`. Папка исключена из Git.

## Правила сравнения

1. Один запуск содержит все 20 раундов. Одна модель получает свой запуск. Другой модели создай отдельный запуск.
2. Каждый раунд начинается в новом чате без истории других раундов. Модель получает только промпт и ссылку этого раунда. Список ответов ей не показывают.
3. На раунд даётся 50 отправок. Неизвестное слово, неверный формат и повтор расходуют отправку. Отправляется одно слово, затем модель читает результат.
4. Промпт предлагает проверять разные смысловые направления и пересматривать гипотезу после холодных попыток. Файлы в `prompts/` являются источником правил. Промпт для конкретного раунда создаёт сервер.
5. Подсказок нет. Любую помощь человека или смену настроек запиши как вмешательство. Перезапуск чата и продолжение не являются новым независимым повтором.
6. Для повторного измерения создай новый запуск с новым номером повтора. Сохрани модель, агента, настройки и интерфейс. Для первого сравнения полезно сделать несколько полных повторов.
7. Сравнивай результаты только при одинаковых отпечатках набора и протокола. Изменение словаря меняет ранги и создаёт другую версию теста.

В режиме `browser` модель работает инструментами браузера, включая JavaScript страницы. В режиме `http` она отправляет запросы HTTP. Качество и время этих режимов сохраняются раздельно в метаданных. Соблюдение режима и отсутствие доступа к ответам обеспечивает оператор. Сервер не контролирует инструменты внешнего агента.

## Оценка

Главные результаты сохраняются отдельно для русского, английского и всех заданий:

| Показатель | Значение |
| --- | --- |
| Доля разгаданных | Число побед относительно всех заданий |
| PAR2 в попытках | Среднее число отправок; неразгаданный раунд получает штраф 100 |
| Попытки в решённых | Среднее и медиана, всегда рядом с долей разгаданных |
| Неизвестные слова и повторы | Расход попыток, который помогает объяснить результат |
| Вмешательства | Запуски с помощью человека отмечаются отдельно |
| Цикл взаимодействия | Время между последовательными результатами в одном раунде |

PAR2 заимствует идею двойного штрафа за неуспех, но здесь единица измерения является попыткой. Незавершённые задания тоже получают штраф 100 в предварительной таблице. Итоговым считается только запуск, в котором все задания решены, исчерпаны или сданы. Кнопка завершения помечает оставшиеся задания как сданные.

Время не входит в оценку качества. `cycle_ms` включает выбор слова, работу агента, инструменты и транспорт. Первый результат каждого раунда исключён. `service_ms` измеряет интервал от получения HTTP-запроса до подготовки изменения состояния, без записи ответа в сокет и фиксации SQLite. Метрики сервера не являются TTFT провайдера. Фактическое время до первого токена можно добавлять отдельно из журналов агента.

Сравнивать только среднее число попыток среди побед недостаточно. Модель, которая решила одно лёгкое задание и сдала остальные, не должна выигрывать у модели, решившей весь набор. Для этого рядом сохраняются доля побед и PAR2.

## База слов и формула

Используется открытая [ConceptNet Numberbatch 19.08](https://github.com/commonsense/conceptnet-numberbatch), файл `mini.h5`. Это 300-мерные векторы в int8. Они построены из ConceptNet и нескольких источников распределённой семантики. Файл источника и его SHA256 зафиксированы в `data/manifest.json`.

Словарь каждого языка формируется из пересечения Numberbatch и частотного списка [wordfreq 3.1.1](https://github.com/rspeer/wordfreq). Берутся частые одиночные слова длиной от 2 до 30 букв, без цифр и дефисов. Выбранные ответы обязательно присутствуют. Регистр игнорируется, Unicode приводится к NFC, русские ё и е объединяются. Если в источнике встречаются обе записи, используется первая по порядку исходного файла. Лемматизации и генерации векторов для неизвестных слов нет.

Для каждого ответа вычисляется косинус между его вектором и всеми векторами словаря:

```text
similarity(w, target) = dot(v_w, v_target) / (norm(v_w) * norm(v_target))
```

Большее значение означает большую близость. Значения округляются до шести знаков. Слова сортируются по убыванию близости. При равенстве порядок алфавитный. Точное совпадение с ответом всегда получает ранг 1, в том числе при совпавших векторах разных слов.

Число ранга не является самим расстоянием. Разность рангов не показывает величину смыслового различия. Добавление слов в словарь меняет ранги даже без изменения векторов.

Ранги рассчитаны заранее и включены в репозиторий. Во время игры сервер ищет готовое значение. Это быстрее и воспроизводимее повторного вычисления векторов на каждом ходе. Словарь, ответы и таблицы рангов не отправляются клиенту. Сервер отдаёт только метаданные заданий и историю конкретного запуска.

## Что удалось установить про исходную игру

В [guess-word.com](https://guess-word.com/) игрок получает порядковый ранг, меньший ранг означает большую близость, ранг 1 завершает игру. Публичный клиент передаёт слово серверу и получает поле `order`. Название embedding-модели и формула серверного расчёта в клиенте не указаны. Этот проект воспроизводит механику, а совпадение оценок с guess-word.com не заявляется.

Открытая [Semantle](https://semantle.com/faq/) подтверждает использование word2vec и базы GoogleNews. В [описании автора](https://legacy.semantle.com/) отдельно указан частотный список, из которого выбирались ответы. Это другой набор, его оценки не смешиваются с нашим.

Выбран Numberbatch, поскольку одна открытая версия содержит оба языка. Русские векторы также доступны в [RusVectōrēs](https://rusvectores.org/ru/models/), но смешивание разных моделей для двух языков добавило бы различия в источниках оценок.

## Ограничения

- 20 заданий дают предварительное сравнение. Они не обеспечивают точный рейтинг близких моделей.
- Ответы выбраны вручную до запусков моделей. В наборе есть конкретные и абстрактные понятия. Сложность заданий ещё не откалибрована по результатам участников.
- Одинаковое число слов не означает одинаковую языковую сложность. Частотность, морфология и качество векторов различаются.
- Word embeddings смешивают значения многозначных слов и сближают слова по контексту. Антоним тоже может иметь хороший ранг.
- Словарь на 50 000 слов остаётся ограниченным. Неизвестное слово не доказывает ошибку рассуждения модели.
- Это фиксированная открытая для оператора выборка. Доступ агента к файлам базы или результатам других попыток делает запуск непригодным для оценки. Для строгой изоляции запускай сервер отдельно от файловой системы участника. Приватность GitHub-репозитория сама по себе такую изоляцию не создаёт.

## HTTP и командный клиент

Для работы с HTTP используй `tools/client.py`. Все запросы обращаются к локальному серверу, ключи провайдеров не нужны.

```sh
python tools/client.py create --model "Gemini 4 Neon" --provider Antigravity --effort high --track http
python tools/client.py prompt RUN_ID ru-01
python tools/client.py guess RUN_ID ru-01 "слово" --request-id UNIQUE_REQUEST_ID
python tools/client.py state RUN_ID
python tools/client.py export RUN_ID --out result.json
```

Для повторной отправки того же запроса после сетевой ошибки используй прежний `request_id`. Сервер вернёт прежний результат без списания ещё одной попытки. Новый идентификатор является новой отправкой.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/suite` | Версия, отпечатки, ID и языки заданий |
| POST | `/api/runs` | Новый запуск с `model`, `provider`, `effort`, `track`, `repetition` |
| GET | `/api/runs/{id}` | История и показатели запуска |
| GET | `/api/runs/{id}/prompt/{round_id}` | Промпт раунда |
| POST | `/api/runs/{id}/guess` | `round_id`, `word`, `request_id` |
| POST | `/api/runs/{id}/abandon` | Сдать `round_id` |
| POST | `/api/runs/{id}/finish` | Завершить оставшиеся задания как неудачи |
| POST | `/api/runs/{id}/intervention` | Записать поле `note` |

Сервер по умолчанию слушает только localhost. Его назначение является локальным экспериментом, а не публичным многопользовательским сервисом.

## Проверки и пересборка

```sh
python -m unittest discover -s tests -v
node --check web/app.js
```

Тесты проверяют правильность всех ответов, смысловую ориентацию рангов, контрольные суммы, бюджет, повторы запросов, штрафы, время циклов, HTTP и отсутствие маршрутов к приватным данным.

Пересборка нужна только при исследовании источника. Она скачивает примерно 604 MiB Numberbatch и требует дополнительных пакетов. Готовой игре эти зависимости не нужны.

```sh
python -m venv .venv
# Windows
.venv/Scripts/python -m pip install -r requirements-build.txt
.venv/Scripts/python tools/download_source.py
.venv/Scripts/python tools/build_data.py
# Linux/macOS: используй .venv/bin/python
```

Сборка читает список ответов из `tools/suite_targets.json`. Это материал оператора, его не дают модели. Зафиксированные файлы `data/*.json.gz` являются источником истины для результатов v1. Если пересборка изменила их отпечаток, её результаты нельзя смешивать с предыдущими.
